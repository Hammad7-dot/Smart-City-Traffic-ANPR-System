## Fixes

- FR4/FR5: OCR now receives original video pixels, not frames contaminated by
  bounding boxes, labels, and the counting line. Annotation uses a separate copy.
- Reliability NFR: plate-detection/OCR exceptions preserve the crossing in SQLite
  and CSV with an empty, low-confidence read. A warning identifies the frame
  without logging potentially sensitive exception text.
- FR5/FR8: missing plate text is flagged in both video and image results, even
  when OCR assigns high confidence to punctuation that normalization removes.
- FR3: invalid counting-line ratios, including NaN/infinity, are rejected before
  creating output files or loading models.
- FR8: the upload confidence slider now reaches video tracking, instead of being
  silently ignored for videos. Invalid confidence values are rejected early;
  the existing default remains 0.3.
- D-008: deduplication searches the preceding five seconds, not every timestamp
  after the cutoff. A future event no longer suppresses an earlier crossing.
- D-024: negative retention days are rejected before any rows are deleted.
- FR6: new database parent directories are created automatically.
- Reliability NFR: invalid sources are rejected before database creation; video,
  CSV, and database resources are closed on partial output setup failure.
- README model availability and H.264 encoding instructions now match the code
  and existing decisions. No new dependencies, schema changes, or threshold
  changes were introduced.

## Remaining limitations

- `python -m pip check` fails in the shared Anaconda environment. Ultralytics
  declares `opencv-python` while this project installs the headless distribution;
  unrelated installed packages also have dependency conflicts. These global
  packages were not modified. D-019's claim that a fresh install cannot pull in
  both OpenCV distributions should not be relied on without a clean-install test.
- Streamlit emits `use_container_width` deprecation warnings. Torch/EasyOCR emit
  quantization and CPU pin-memory warnings. These did not fail the checks above.
- OCR accuracy is not established by unit tests or successful video processing;
  it needs labeled, representative footage. Existing D-022 limitations remain.
- Retention remains manual/externally scheduled, and generated videos/CSVs are
  not covered by the database purge. No deployment privacy policy was changed.
- Test outputs and any real-video review artifacts stay under gitignored
  `output/`; no model weights, sample footage, or plate records are committed.
